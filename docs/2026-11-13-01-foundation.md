# Foundation setup

Plan 02 has since added server-backed data and authentication; see
[saved notes and people](./2026-11-13-02-saved-notes-and-people.md) for current setup.
The implementation boundary and verification below record the Plan 01 snapshot.

This is the implementation entry point for the Next/Cloudflare foundation. The

## Toolchain

Use Node 24 and Bun 1.4.0. Dependencies are locked in `bun.lock`:

| Dependency              | Version           |
| ----------------------- | ----------------- |
| Next / React            | 16.4.6 / 19.3.1   |
| OpenNext / Wrangler     | 1.20.17 / 4.162.0 |
| AI SDK / React bindings | 7.0.173 / 4.0.177 |
| Zod / Zustand           | 4.6.7 / 5.1.0     |
| Drizzle ORM / Kit       | 0.45.4 / 0.31.11  |
| ESLint / TypeScript     | 9.39.5 / 6.0.3    |
| Prettier / Playwright   | 3.10.1 / 1.65.1   |
| Workers OTel / OTel API | 2.1.7 / 1.9.1     |

TypeScript stays below 6.1 for typescript-eslint support. ESLint 9 matches the React
plugin's declared support. OTel API 1.9.1 satisfies the Workers SDK's `<1.10.0`
peer constraint; upgrading it independently would break that contract.

## Commands

```bash
bun install --frozen-lockfile
bun run dev
```

The Next development server is at port 3000. Its OpenNext development integration
provides Cloudflare context for local bindings. Optional provider keys are private
environment settings; none are needed to render or navigate the shell.

```bash
bun run format:check
bun run lint
bun run typecheck
bun run test:worker
bun run build:worker
bun run deploy:check
bunx --no-install playwright install chromium
bun run test:e2e
```

`lint` and `typecheck` generate Worker and Next route types so they work on a clean
checkout before a build. `typecheck` checks web, tooling, Worker and Worker-test
source separately. Worker runtime declarations do not leak into browser code.
ESLint includes typed promise/unsafe-value checks, Core Web Vitals, React Hooks,
exhaustive switches and import boundaries. Prettier owns formatting. Generated
output and isolated benchmark experiments are excluded from root format/lint.

`build:worker` builds the production environment through OpenNext. `deploy:check`
packages it without deployment. Playwright launches that artifact in local
workerd on port 8787 and refuses to reuse a potentially unrelated server.

For an interactive preview after building:

```bash
bun run preview:worker --env production
```

The CI workflow runs the same checks on Node 24, installs Chromium and retains
failure traces/screenshots. Shell tests block API/provider calls; health tests
call only the local health route. `test:worker` uses Node's test runner and the
same Miniflare/workerd generation used by Wrangler. It captures real OTLP exports
locally and verifies async context, export filtering, disabled export and collector
failure. No real Logfire token or external collector is used in these tests.

## Runtime

- `wrangler.jsonc` declares distinct staging and production Worker names.
- `worker.ts` wraps the generated OpenNext handler for request-lifetime tracing.
- No application database, R2 bucket, Queue or Durable Object is provisioned by
  this foundation. Later plans add their bindings when those features land.
- `open-next.config.ts` uses adapter defaults. Distributed Next cache services
  are not assumed or silently provisioned.
- `types/open-next.d.ts` describes the generated handler's public contract so a
  clean checkout can typecheck before the generated JavaScript exists.
- `public/_headers` gives fingerprinted Next static files immutable caching.
- Regenerate types after changing Wrangler bindings. `cloudflare-env.d.ts` is
  generated and ignored; `secrets.required: []` keeps optional local secret names
  out of generated types and lets the shell run without provider credentials.

`src/db/client.ts` is still unused prototype scaffolding. Activating persistence
requires the request-scoped Hyperdrive/database work in the next plan.

## Optional Logfire tracing

The sole provider initialization is the Workers wrapper using
`@pydantic/otel-cf-workers`. Do not also initialize Node/Vercel telemetry in the
same Worker. The standalone Next dev server has no exporting SDK.

For local preview, copy `.dev.vars.example` to `.dev.vars` and set a Logfire
project write token and the project's region-specific base URL. A `.dev.vars`
file replaces Wrangler's `.env` loading, so include needed provider keys there
too. For deployed environments, use Wrangler secrets for tokens; never commit
them. `LOGFIRE_ENVIRONMENT` accepts development, staging or production.

Only the explicit `GET /api/health` and `check health` spans are exported in this
baseline. They contain a generated `request.id`, status and timing. Framework
spans, arbitrary headers/URLs, user content and exception text are filtered out.
No token/base URL means no export. Later features deliberately add their own
named operations and attributes.

Request `/api/health` and use the returned `requestId`/`x-request-id` to locate the
trace under service `voidnote`. The response is uncached and requires no provider
or database. Export work is tied to the request through `ctx.waitUntil()` and
must not determine response success.

Live Logfire ingestion requires choosing a VoidNote project and supplying its
write token. MCP read access alone does not provide an ingestion credential.

## Implementation boundary

The foundation upgrades the shell; it does not establish the production MVP's
data guarantees. Notes still use localStorage, recordings still use the existing
IndexedDB lifecycle, and current diarization/chat routes are prototype paths.

React migration fixes remove mirrored state/init loops and ignore obsolete async
UI results. They do not implement detached runs, atomic remote capture or durable
speaker correction. AI SDK is installed for the later agent work; the prototype
chat endpoint has not yet been migrated to it.

Next: saved notes/auth/people, then durable recording, timestamped processing and
speaker correction. Those features each own their schema, tests and adapter work.

## Verification — 2026-11-13

Completed locally on Node 24 with the locked dependencies:

- Frozen install, formatting and zero-warning typed lint.
- Web, tooling, Worker and Worker-test TypeScript checks. A source-only temporary
  checkout also passed type generation/checks without an existing Next build.
- Next/OpenNext production build and staging/production Wrangler packaging dry runs.
- Five Playwright tests against the production workerd preview: note creation and
  reload, selected-note restoration, chat initialization/send regression, concurrent
  health IDs and caller-metadata isolation. Chat responses are local fixtures.
- Four real workerd telemetry tests: related exported spans, concurrent async
  context/filtering, stalled/failing exporter isolation and missing-token behavior.
  The collector's HTTP 503 log is deliberately injected by the failure test.

Cloud deployment and live Logfire ingestion have not been performed. The available
Logfire MCP projects did not include VoidNote; a project and write token still need
to be configured. The local exporter tests require neither and make no external
collector requests.
